4. Full mirror versus action log

Concern A. Row mirror B. Action log
Server code to accept a write Generic: validate columns, upsert Must run the app's reducer in the Worker
Swift work per app Outbox and row apply, generated types Port every reducer, keep it identical forever
Agent changes a schema Edit schema.ts, generate, additive ALTER on both sides Version the action, keep old handlers, replay the log to rebuild state
Backwards compatibility None needed; clients re-pull on hash mismatch Action definitions can never be removed
Client-side complexity Apply rows, reload snapshot Undo pending, apply remote, replay pending
Conflicts Column LWW; "increment" style intents collapse Intent preserved, deterministic order
Audit, undo, activity feed Needs a server log of row writes (procrastimate has one) The log is the data
Non-sync readers (agent API, push cron, backups) Read tables directly Read a materialized view that must stay in step
Precedent PowerSync, Replicache, Evolu, both apps today LiveStore (beta, no Swift, no compaction, no conflict handling yet)

Verdict: A. The one thing B buys that matters here, intent-preserving merges, both apps already avoid by sending resulting values (procrastimate completes a recurring task by sending the next due date, not "advance"). Keep an append-only log of applied row writes in the object for activity and debugging. That is a cheap table, not a second sync model.

5. Where the server runs

Option Free tier (2026-10) Live updates New environment Local, no cloud Fit
Cloudflare Durable Object, SQLite 100k req/day, 5M reads, 100k writes/day, 5 GB WebSocket with hibernation none: object exists on first use wrangler dev, about 1 s Pick. Strict per-space ordering for free.
Cloudflare D1 + Worker same quotas, 10 databases, 500 MB each polling, or a DO anyway wrangler d1 create; 10 DBs caps environments wrangler dev Fallback adapter only.
Turso + Lambda or Vercel 100 DBs, 5 GB, 10M writes/mo none from the function; needs a push service turso db create, seconds turso dev; function emulators vary Portable second home. Swift SDK is a preview. Every query is an HTTP hop.
Lambda + DynamoDB 1M req, 25 GB, 25 RCU/WCU needs API Gateway WS or AppSync IaC per environment DynamoDB Local is Java/Docker Not SQL: breaks "same schema everywhere".
Neon or Supabase Postgres Neon 20 GB, cold start 0.5 to several s; Supabase pauses after 7 idle days needs a service CLI Docker Postgres on the server, SQLite on the client: the type mapping we have now.
Self-hosted PowerSync, Fly no free tier; $2.19/mo smallest machine plus volume built in containers, storage DB, replication slot Docker Always-on by design (one replicator process).

Free-tier headroom, measured against the one-user numbers from procrastimate's Turso days (about 1.5k rows total, writes at keystroke speed folded by a 100 ms throttle): one push is one request and roughly 3 to 6 row writes including indexes, so the 100k rows written per day allows on the order of 15k pushes a day. A 1,000-task import costs about 5k row writes once. Deno Deploy is excluded: Deno announced on 2026-10-09 that Deploy shuts down in about six months.
